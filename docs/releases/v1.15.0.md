# v1.15.0 · SSO 多样本续期与超时保护

本版本由 `aiis2` 整理并发布，解决批量重新授权长期依赖单一预检账号的问题。预检现在会覆盖不同时间端点、序列位置和凭据来源；单个账号失效或超时不会永久阻断整个账号池，同时保留连续服务端拒绝时的安全熔断。

## 主要变更

- 重新授权候选跨当前目录和历史目录按文件时间全局排序，并按稳定身份去重，避免目录优先级和重复记录影响抽样。
- 主样本固定覆盖最老、最新和中位位置，并尽量选择不同来源；零成功且失败信号不一致时，可继续尝试四分之一和四分之三位置的备用样本。
- 任一健康样本成功即可释放剩余批量；已完成的样本不会再次入队，也不会重复计数。
- 单样本最长 60 秒、整个预检最长 120 秒；deadline 贯穿 OAuth HTTP 请求、Next.js 脚本发现、consent 锁、冷却等待、退避和重试。
- 三个不同身份返回相同系统错误签名时才触发系统性熔断；明确 `access_denied` 仍只禁用实际收到拒绝的账号。
- 修复批量入队、worker、提交器和熔断并发下的计数竞态，保持 `run_ok + run_fail + run_skipped == run_total`。
- Next.js consent action 缓存绑定当前部署脚本集合，上游部署变化后会自动重新发现 action id。
- 重新授权路径的 API、日志和失败记录只保留脱敏错误分类；Token 非 JSON 响应不再拼接原始正文。
- 禁用账号登记的跨进程锁改为有界等待和失败关闭，避免锁竞争造成无限卡住或静默覆盖。

## 行为说明

- 首个样本失败、账号失效或达到样本 deadline 后，系统仍会测试不同时间和序号的样本。
- 三个主样本中只要一个成功，成功凭据会先原子提交，然后释放其余候选进入 CPA 队列。
- 如果样本全部失败且错误信号混合，系统会继续使用备用样本；只有一致的系统错误证据才会提前熔断。
- 批量阶段仍保留连续拒绝熔断。达到阈值后，未尝试账号计入跳过并保留原凭据，不会为了跑满数量而绕过 x.ai 的授权决策。
- 非 `access_denied` 失败保留已有 CPA；明确拒绝的账号进入本地禁用池并从后续导出中排除。

## 升级说明

1. 停止旧面板并保留本地 `config.json`、`data/credentials/` 与 `data/logs/`。
2. 更新项目文件后通过 `start.bat` 或 `启动.bat` 重新启动面板，确保 launcher 传递当前可用代理。
3. 在“凭据 → CPA 转换”点击“重新生成账号授权”，观察预检样本摘要和批次终态。
4. 如果批次因连续 `access_denied` 暂停，请保留未尝试账号，确认授权条件恢复后再开启新批次。

## 安全边界

- 本功能只改进抽样、超时、诊断和失败隔离，不伪造身份、不绕过 x.ai 授权决策，也不会强制重试已明确拒绝的账号。
- 禁用账号登记和 CPA 凭据仍属于本地敏感数据，不应提交、上传或加入公开 Release 资产。
